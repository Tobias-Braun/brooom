# CLAUDE.md

## Tool use Policy

Prefer simple editing / reading tools over bash commands, wherever possible. Examples:

- Edit >>> Bash(echo 'content' >> file)
- Search(pattern) >>> Bash(cat file | grep pattern)

Reduce Bash Tool usage to a minimum of well-known commands whenever possible (no hard guardrail).

## Comments

Do not use one-line commands to just mark a section. Comments should always be explanational.
Use long explanatory doc comments if code is not self-explanatory. Use short in-line comments if the reason for a specific line seems unambigious. Use a short one-line comment if code needs to violate a rule that otherwise is present in projects.

## Git Identity

The commit identity is chosen by folder via `includeIf` in `~/.gitconfig`: repos under `/Volumes/Developer/Developer/private/` and `/Volumes/Developer/Developer/dotfiles/` commit as tobiasmarkusbraun@gmail.com, everything else as tobias.braun2@adesso.de. Do not override `user.email` per repo.

## Commits, pushes and pull requests

Commits and pushes are always done through the `git` CLI, as the configured git user (see Git Identity). Never author them as Claude: no Claude identity, no `Co-Authored-By` trailer and no "Generated with Claude" lines in commit messages or PR descriptions.

Pull requests are created and merged through the GitHub CLI (`gh pr create`, `gh pr merge`). Where `gh` is unavailable or unauthenticated (e.g. cloud sessions), the GitHub MCP server is the alternative. Never use the web UI.

## Code requests

Whenever the user asks for some implementation or code change to be done, treat it as an invocation of the `/issue` skill (`/issue <description>`) rather than implementing it directly inline.

## API routing

There is a single Claude config (`~/.claude`) using the personal claude.ai login. Some folders carry a `.claude/settings.local.json` (generated by `scripts/claude-gateway-init`) that routes requests through a LiteLLM gateway (key via `apiKeyHelper` from the macOS Keychain). Never write API keys into settings files.
